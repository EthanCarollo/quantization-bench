02 — LES MESURES

Trois façons
de rester dans le rôle.

Chaque colonne répond à une question différente. Les valeurs n’ont pas la même signification d’un benchmark à l’autre.

01

RoleBench · généralisation

10 prompts de test en anglais sur des rôles fixes. ROUGE-L F1 compare chaque réponse à la première réponse de référence RoleGPT. Cela mesure le chevauchement de formulation, pas une note humaine de qualité.

10 prompts · 5 runs · graine fixe
02

RoleBench · rôle spécifique

Les mêmes 10 rôles, mais des questions et références différentes, conçues pour tester les réponses spécifiques au rôle. Les scores de cette piste restent distincts de ceux de généralisation.

10 prompts · mêmes rôles · questions différentes
03

CharacterEval · CharacterRM

12 exemples chinois, un personnage par exemple, choisis pour couvrir les 12 dimensions disponibles. Le reward model CharacterRM note les réponses de 1 à 5; le score est transformé linéairement en 0–100 et les dimensions sont pondérées à égalité.

12 exemples · 12 dimensions · évaluateur entraîné sur des annotations humaines

03 — COMMENT LIRE LE PROTOCOLE

Des choix visibles.
Des comparaisons utiles.

Modèles et quantifications utilisent les mêmes prompts et paramètres de génération au sein d’un benchmark. Les données brutes, versions des sources et sommes de contrôle sont conservées dans le dépôt.

A

Modèles comparés

Google Gemma 4 E2B IT (2,3B paramètres actifs, 5,1B avec embeddings) et Qwen3-4B (4,0B au total). Les poids et jeux de données sont épinglés à des révisions précises. Les modèles sont exécutés en MLX sur Apple Silicon.

Gemma 4 E2B ITQwen3-4BMLX 4-bit / 8-bit
B

Quantification

MLX affine, poids quantifiés par groupes de 64; les autres tenseurs restent en bfloat16. Les variantes GGUF prévues sont BF16, Q8_0 et Q4_K_M. Aucun score GGUF n’est publié tant que ses cinq runs ne sont pas complets.

C

Répétitions et incertitude

Chaque variante a un échauffement non noté puis cinq graines fixes. Le tableau présente la moyenne des scores par run et l’écart-type d’échantillon entre les runs. L’écart-type décrit la variation observée, pas un intervalle de confiance.

D

Génération

RoleBench et CharacterEval: température 1, top-p 0,95, top-k 64, réflexion désactivée, limite de 512 nouveaux tokens. Les réglages officiels propres à IFBench, HLE et LiveCodeBench s’appliquent lorsqu’ils seront exécutés.

01

Préparer l’environnement

Génération: macOS, Apple Silicon, Python 3.13. Acceptez les conditions Gemma et définissez HF_TOKEN. HLE demande aussi l’accès au jeu et OPENAI_API_KEY pour le juge. CharacterEval se score à part sur CUDA; LiveCodeBench exécute le code dans Docker isolé.

Afficher les commandes complètes+
python3.13 -m venv .venv
.venv/bin/pip install -r requirements.txt

.venv/bin/python scripts/prepare_rolebench_subset.py
.venv/bin/python scripts/prepare_charactereval_subset.py
.venv/bin/pip install -r requirements-ifbench.txt
.venv/bin/pip install -r requirements-hle.txt
.venv/bin/python scripts/prepare_livecodebench.py

# Accept Gemma's Hugging Face terms and provide HF_TOKEN before conversion.
# HLE also needs gated dataset access and OPENAI_API_KEY for its judge.
for model in gemma4_e2b_it qwen3_4b; do
  for bits in 4 8; do
    .venv/bin/python scripts/convert_model.py --model "$model" --bits "$bits"
    for benchmark in rolebench_generalization rolebench_role_specific; do
      .venv/bin/python scripts/run_benchmark.py --model "$model" --benchmark "$benchmark" --bits "$bits"
    done
    .venv/bin/python scripts/run_charactereval.py --model "$model" --bits "$bits"
    .venv/bin/python scripts/run_ifbench.py --model "$model" --bits "$bits"
    .venv/bin/python scripts/run_hle.py --model "$model" --bits "$bits"
    .venv/bin/python scripts/run_livecodebench.py --model "$model" --bits "$bits"
  done
done

# HLE's official structured-answer judge (makes API requests).
for model in gemma4_e2b_it qwen3_4b; do
  for bits in 4 8; do
    .venv/bin/python scripts/evaluate_hle.py --model "$model" --bits "$bits"
  done
done

# Build the isolated LiveCodeBench checker, then evaluate generated code.
docker build -f docker/livecodebench/Dockerfile -t roleplay-bench-results/livecodebench-evaluator:28fef95 .
for model in gemma4_e2b_it qwen3_4b; do
  for bits in 4 8; do
    .venv/bin/python scripts/evaluate_livecodebench.py --model "$model" --bits "$bits"
  done
done

# On a CUDA host, after copying this repo and generated CharacterEval files:
python3 -m pip install -r requirements-charactereval-evaluator.txt
python3 scripts/evaluate_charactereval.py \
  --profiles data/charactereval-mini/character_profiles.json \
  --offload-dir /path/to/charactereval-offload \
  results/*_charactereval_mlx_*bit.jsonl

.venv/bin/python scripts/summarize.py

Le script de synthèse régénère le CSV, le JSON et la copie de données utilisée par cette page.
